How to interpret this dashboard

What data is shown?

The table is generated from the public-ai sovereignty pipeline, which evaluates models using Hugging Face metadata and, optionally, supporting web evidence. Each entry includes a sovereignty score and a breakdown across seven independence dimensions, with verified quotes where available.

In this demo, the dataset is a static snapshot (data/models.json) organised by Hugging Face author/organisation. Each organisation block contains metadata (country, type, aggregate scores) and one or more evaluated models. In a full deployment, this would be continuously generated by analysing live model cards, organisation metadata, and external documentation.

What “sovereignty” means here

In this dashboard, sovereignty refers to the degree of control, independence, and local alignment of an AI model. This includes:

  • Whether the model can be run and controlled independently
  • Whether its development is tied to a specific country or institution
  • How transparent its data and training process are

This definition intentionally combines technical, organisational, and geopolitical factors into a single comparative framework.

Dimensions used

Each model is evaluated across seven dimensions of AI sovereignty (independence from Big Tech control):

  • Training Data Independence – whether training data is self-owned or openly licensed, without dependence on proprietary Big Tech pipelines
  • Compute Independence – whether training used sovereign or public HPC infrastructure rather than commercial cloud hyperscalers
  • Weight Ownership & Access – whether weights are openly released with no revocable access restrictions
  • Base Model Dependency – whether the model was trained from scratch or derived from another (especially proprietary) model
  • Deployment Independence – whether the model can be run locally or on-prem without a proprietary API gate
  • Organisational Independence – whether the developer is a public institution, independent org, or Big Tech subsidiary
  • Jurisdictional Risk – exposure to extraterritorial data-access laws (e.g. US CLOUD Act, Chinese cybersecurity law)

Each dimension is scored between 0 and 1, where higher values indicate greater sovereignty along that axis.

How scores are calculated

Each dimension starts with a neutral score of 0.5, then is adjusted using heuristics derived from Hugging Face model metadata (licence, base model, author, tags) and organisation context (country, institution type):

  • Open licences increase weight ownership but may reduce deployment restrictions
  • Presence of a base model lowers base-model independence (indicating fine-tuning)
  • Known public or state-backed organisations increase compute and organisational independence
  • Jurisdiction is inferred from organisation metadata and country signals

When web evidence is enabled, the pipeline searches and scrapes external sources per dimension, then either:

  • Applies keyword-based heuristic adjustments (e.g. “sovereign”, “open data”)
  • Or uses a language model to extract scores and verified quotes from external sources

The final score is a weighted average of all seven dimensions (equal weighting by default), scaled to a 0–100 range.

Data sources and signals

The pipeline relies primarily on structured metadata from Hugging Face, including model cards, tags, licences, and organisation names. Additional signals may be extracted from external web documents when available.

Because metadata is often incomplete or inconsistent, the system uses heuristic pattern matching rather than strict verification. This allows broad coverage but introduces some uncertainty.

Interpretation and limitations

This score is a heuristic approximation, not a definitive label. It blends multiple interpretations of sovereignty—such as openness, control, and national alignment—which can sometimes conflict. For example, open weights increase usability and control, but reduce privacy.

Scores are sensitive to metadata quality and should be interpreted as directional indicators rather than precise measurements. The dashboard is best used for comparison and exploration, alongside detailed model documentation.
